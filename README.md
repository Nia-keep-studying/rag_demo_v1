# RAG Demo V1

一个用于学习的 Python RAG 项目：读取 Markdown 示例制度，按章节切片，使用本地 Embedding 模型检索，再调用 DeepSeek 根据资料回答并标注来源。

当前包含 3 份示例制度、12 个片段。这些文档用于练习，不代表真实企业政策。

## 当前流程

```text
Markdown 文档 → 按二级标题切片 → 章节与正文向量化
用户问题 → 表达映射 → 关键词候选
用户问题 → 问题向量 → min_score 过滤 → 相似度排序 → 最多 3 个向量候选
两路候选 → 关键词在前、向量补充 → 按来源和片段编号去重
有片段 → 带来源的参考资料 → DeepSeek 回答
无片段 → 程序直接提示无法确认，不调用回答 API
```

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `rag_loader.py` | 读取文档并保留来源、章节、片段编号 |
| `rag_search.py` | 表达映射、关键词检索、两路合并去重与上下文 JSON 构造 |
| `vector_search_demo.py` | 人工二维向量的余弦相似度、Top K 和阈值练习 |
| `embedding_demo.py` | 加载真实模型、生成片段向量、按相似度检索 |
| `rag_answer.py` | 混合检索与 DeepSeek 回答的完整流程 |
| `eval_retrieval.py` | 两题批量检索、预期来源与章节匹配、命中计数；不调用回答 API |
| `documents/` | 三份示例制度文档 |

## 环境与安装

已在 Windows、Python 3.12 环境中运行。代码使用 Python 3.12 的 f-string 语法，请使用 Python 3.12 或更高版本；其他版本与平台尚未完整验证。依赖版本来自当前可运行环境，尚未进行全新环境安装验收。

在 PowerShell 中执行：

```powershell
git clone https://github.com/Nia-keep-studying/rag_demo_v1.git
cd rag_demo_v1
py -3.12 -m venv .venv312
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt
```

如果没有 `py` 启动器，用本机 Python 3.12 的可执行文件路径替换 `py -3.12`。命令直接指定虚拟环境中的 Python，因此无需先执行激活脚本。

## 配置与运行

完整问答需要 DeepSeek API Key。首次配置时复制模板，并在本机编辑 `.env`：

```powershell
Copy-Item .env.example .env
```

将 `.env` 中的占位符替换为自己的 Key。已有 `.env` 时不要覆盖。真实 Key 不要写进源码或提交到仓库。

分别运行：

```powershell
# 只检查文档加载和切片，不调用外部模型 API
.\.venv312\Scripts\python.exe rag_loader.py

# 本地向量诊断，目前输出全部片段与分数
.\.venv312\Scripts\python.exe embedding_demo.py

# 自动检索评估，不调用回答 API
.\.venv312\Scripts\python.exe eval_retrieval.py

# 完整 RAG 问答，有候选时调用 DeepSeek API
.\.venv312\Scripts\python.exe rag_answer.py
```

本地 Embedding 使用 `cnmoro/multilingual-e5-small-distilled-16m`，首次运行需要从 Hugging Face 下载模型，缓存在项目 `.model_cache/` 下。模型以归一化方式生成 64 维向量，使用点积计算相似度。文档与问题由本地模型编码；有候选片段时，完整问答会将问题和召回的资料发送给 DeepSeek，并产生 API 费用。空结果时不会调用回答 API；当前客户端仍在程序开始时创建，因此依然需要配置 Key。

这个环境曾遇到 FastEmbed / ONNX Runtime 原生 DLL 加载失败，目前使用 Model2Vec，不需要安装 FastEmbed。

## 历史观察与基准

- 文档加载得到 3 份文档、12 个片段。
- “发货后还能修改收货地址吗？”：地址修改片段进入前三名，回答引用对应制度。
- “可以开电子发票吗？”：加入阈值前，虽然检索返回候选，模型在人工验收中回答无法确认；加入 `min_score=0.6` 后，候选为空，程序直接提示无法确认。
- “货物寄出去以后还能调整收件地点吗？”：曾观察到地址修改排第 7，Top 3 漏召回。这是保留的失败案例。

以上为当前小样例的观察，不代表对所有提问都能稳定回答或拒答。相似度分数不是正确率，具体排名也不是业务事实。

固定 `top_k=3`、`min_score=0.6`。下表是学习者完成的五题检索验收；无答案题的“返回空结果”算符合预期，不能与有答案题的漏召回混为一谈。

| 问题 | 预期依据 | 手动测试结果 |
| --- | --- | --- |
| 发货后还能修改收货地址吗？ | 发货管理制度／地址修改 | 命中 |
| 货物寄出去以后还能调整收件地点吗？ | 发货管理制度／地址修改 | 未命中，保留失败案例 |

这是小样例基准，不等同于系统总体准确率。后续改进时保留原问题措辞，并增加未参与调整的新问法。

## 2026 年 10 月 4 日改进与验证

- 映射“收件地点”等表达到“地址”，关键词候选补回原第二题。
- 新句子“包裹已经寄出了，还能换个地方接收吗？”正确章节约 0.541、排第三，原 0.6 阈值会过滤它。当前问答和评估显式传入 `top_k=3`、`min_score=0.526`；学习者报告六题复测符合预期。
- 三道新增人工观察中，退款回答区分发货前后，到货回答区分发货与送达，无依据成本问题正确拒答；仍存在无关召回。
- 自动评估目前只有两个地址问题，比较最终候选的文件与章节。2026-10-04 本地缓存模型离线运行输出 `总命中数：2/2`，未调用回答 API。它不评估答案质量，也不代表通用准确率；两题已参与过开发调整。
- 合并后按关键词在前、向量补充的顺序保留片段，最终数量可能超过 3。尚未使用重排序或分数融合。

## 当前边界与下一步

- 问答与评估使用 `top_k=3`、`min_score=0.526`；函数默认仍为 3 和 0.6；独立向量演示使用 `top_k=len(chunks)`、`min_score=-1.0` 查看全排名。参数用途不同，阈值不是正确性保证。
- 空候选由程序直接处理；有候选但资料不足时，仍依赖提示词与生成模型判断拒答。
- 关键词映射及两路合并已实现，检索与合并函数在 `rag_search.py` 中共用；映射仅覆盖手工列出的表达。
- 每次运行会重新生成文档向量；尚未使用持久化向量数据库。
- Markdown 切片只适配当前二级标题结构；尚未处理复杂表格、PDF、跨章节指代和版本冲突。
- `rag_answer.py` 当前是交互式入口脚本，导入时也会执行输入及运行流程；请直接运行该脚本。
- 已有自动检索评估初版；尚未加入生产环境权限控制、重排序、无依据题自动评分和完整异常处理。

下一步扩充自动评估题目、明确无依据题评价规则并保存结果，再做重排序对照。缓存、版本检测及复杂文档解析目前仅讨论概念，未实现。

`.env`、虚拟环境、模型缓存、数据库和 Python 缓存已通过 `.gitignore` 排除。
