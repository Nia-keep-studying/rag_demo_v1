# 早期 RAG 学习记录

以下保留 2026 年 10 月 3 日至 5 日的历史观察。文中的“当前”“尚未实现”以各节日期为准，不代表最新版状态；实际配置见项目 README，10 月 6 日结果见 EXPERIMENTS.md。历史测试问法与参数均保留，不把它们改写为新配置的验证结论。

## 历史观察与基准


- 文档加载得到 3 份文档、12 个片段。
- “发货后还能修改收货地址吗？”：地址修改片段进入前三名，回答引用对应制度。
- “可以开电子发票吗？”：加入阈值前，虽然检索返回候选，模型在人工验收中回答无法确认；加入 `min_score=0.6` 后，候选为空，程序直接提示无法确认。
- “货物寄出去以后还能调整收件地点吗？”：曾观察到地址修改排第 7，Top 3 漏召回。这是保留的失败案例。

以上为当前小样例的观察，不代表对所有提问都能稳定回答或拒答。相似度分数不是正确率，具体排名也不是业务事实。

## 2026 年 10 月 4 日改进与验证

- 映射“收件地点”等表达到“地址”，关键词候选补回原第二题。
- 新句子“包裹已经寄出了，还能换个地方接收吗？”正确章节约 0.541、排第三，原 0.6 阈值会过滤它。当前问答和评估显式传入 `top_k=3`、`min_score=0.526`；学习者报告六题复测符合预期。
- 三道新增人工观察中，退款回答区分发货前后，到货回答区分发货与送达，无依据成本问题正确拒答；仍存在无关召回。
- 自动评估目前只有两个地址问题，比较最终候选的文件与章节。2026-10-04 本地缓存模型离线运行输出 `总命中数：2/2`，未调用回答 API。它不评估答案质量，也不代表通用准确率；两题已参与过开发调整。
- 合并后按关键词在前、向量补充的顺序保留片段，最终数量可能超过 3。尚未使用重排序或分数融合。

## 2026 年 10 月 5 日评估与重排序实验

- 自动评估加入无依据电子发票题；有依据题按文件和章节匹配，无依据题按候选为空判断。离线复核三题 `passed=true`，汇总 `检索检查通过数：3/3`，没有调用回答 API。结果保存为当前一轮快照，后续运行会覆盖；不是整体回答准确率。
- 重排序模型使用 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，本地 CPU 执行，首次需要下载。它对问题与章节正文配对评分，再按分数倒序排序，当前最终保留 2 项；分数是原始相关性得分，不能复用向量阈值。
- 原问题“包裹已经寄出了，还能换个地方接收吗？”的状态限制约 -0.960、发货后退款约 -2.319、地址修改约 -2.679。正确章节排第三，截前二会丢掉。保留失败，不反转排序。
- 对照明确问法“订单已经发货，还能修改收货地址吗？”时，地址修改约 9.679、状态限制约 3.289、发货后退款约 0.312，地址修改排第一。这只是诊断，不代表原问题修复；脚本已恢复从 JSON 读取原问法。
- 检查配对、截断和单条批量得分后，当前证据显示这组改写表达上排序不稳定。重排序没有接入完整问答，下一步以可关闭方式做对照，不默认开启。
- 七个 Python 文件语法检查通过。依赖版本已补到清单，尚未做干净环境安装验收。

Windows 曾出现 PyTorch `c10.dll` 初始化失败。学习者更新 Microsoft VC++ 运行库后成功导入；是否同一原因仍需依据实际环境判断。官方运行库说明：https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/ 。当前学习环境使用 CPU 版 PyTorch；如需明确使用 CPU 版，可先执行 `python -m pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu`，然后再安装其余依赖。
